## Limits of this check

- Verdicts are read from the code at the review commit; rerun flags features whose matched files changed since then, and those need a fresh read before their verdict is trusted.
- No feature is `verified`: nothing in these areas reaches real data in the running app yet, so no behaviour could be compared with the reference. Screens compare our browser build (sample diff data, local placeholder chat) with the reference harness captures.
- Ledger obligations for these areas are all still `unowned`/`blocked` (none `verified`).
