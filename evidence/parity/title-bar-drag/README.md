# Title-bar drag region

Why the window did not move: Tauri's injected drag script answers a press on a
`data-tauri-drag-region` element by invoking `plugin:window|start_dragging`, and
Tauri 2.12's `core:window:default` does not include `core:window:allow-start-dragging`
(crates/tauri/permissions/window/autogenerated/reference.md at tauri-v2.12.5). Our
capability only listed `core:default`, so every drag was denied by the ACL.
Conductor's own frontend calls `plugin:window|start_dragging`
(evidence/ipc/tauri-plugin-commands.txt).

Fix: grant `core:window:allow-start-dragging` to the main window; in the workspace
header the title (breadcrumb, branch and status chips) is a `deep` drag region,
the target-branch picker opts out with `="false"`, and the gaps in the header
actions and in the sidebar's back/forward group are drag regions. Buttons never drag.

Probe (press-probe.*.json): the built frontend served in headless Chromium
1440x900 / 1280x820 with Tauri 2.12.5's drag.js (os = macos) injected and invoke
stubbed; a real CDP mouse press at each point, recording whether start_dragging
was invoked. main: only the bare header padding and the sidebar top bar dragged;
this branch: breadcrumb, workspace name, chips and the action/history gaps drag
too, while buttons and the chat area do not. Share of the top 110 px that starts a
drag: 42.6% on main, 49.3% on this branch.

Not verified here: a real window drag in the built Tauri app (this Linux cloud
machine has no webkit2gtk and no display session for it), and Conductor's own drag
regions through REA on Sven's Mac (not reachable from this Session).
