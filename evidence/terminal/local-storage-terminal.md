## Our choices where we differ

- The backend writes the file, not the frontend: it already writes `local-storage.metadata.json` for terminal history, so it stays the only writer. The commands are ours; the reference has none, because its frontend writes through the fs plugin.
- Writes are not debounced. One `local_storage_set_entry` writes the store file, then the index, while holding the lock. The tab list changes only when tabs change. Evicted entries leave the store file in the same write; the reference removes them in a later write within its 100 ms debounce.
- The store file's keys are written sorted (serde_json's map), not in insertion order. With one key, the files are identical.
- `content` crosses IPC as JSON text (`JSON.stringify` in the webview), so sizes and stored bytes are exactly what the reference's `JSON.stringify` gives. The backend checks only that the text is JSON.
- Our tab entries also carry `title`, and the state carries `titleCounters` (`[[workspaceId, next]]`), because our panel numbers its tabs ("Terminal 3"). The reference's merge ignores both. A record without them gets `Terminal 1..n` and a counter of `n + 1`.
- `startingCommandRan` is always written `false`; we do not track it per tab. `lastTabKind` becomes `terminal` on every save, since our panel has only terminal tabs; the reference sets it only when a tab is selected. `hostKind` is not written.
- An active `run` or `setup` tab, and repository terminals (`repositoryId`, no workspace), are dropped when read; we have neither.
- If the first read of a launch fails, nothing is written that launch, so a list we could not read is never replaced.
- Our earlier builds kept the list in the webview's `localStorage` under the same key, in our own format. On the first read, when the backend has no entry, that copy is moved and then removed. If the move cannot be written, the copy stays for the next launch.
- Outside the desktop app (vite dev in a browser), the entry is kept in the webview's `localStorage` as `local-storage:terminal:terminal-panel-tabs-v1`.
- Subsystem `terminal-history` is refused by `SubsystemStore`, and any subsystem the index keeps as entry files is refused with `entryStorageMismatch`. The reference's store follows the existing record's storage kind instead.
