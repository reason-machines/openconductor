Cursor theme does not follow terminal lifecycle

The retained Conductor renderer assigns a transparent cursor when input is disabled. Current OpenConductor disables stdin after exit but leaves its cursor theme unchanged.

Supported: a theme-option contract difference. Not observed: real cursor rendering, installed-app behavior, native execution, shell redraw or PTY reuse. Nine regression cases are authored and frozen. Product tests have not run; the four-line cursor-theme candidate is not applied.

Why read-only stdin does not close the difference

The existing pinned xterm 6.0.0 dependency maps disableStdin to textarea read-only/input admission. Its DOM renderer checks cursor initialization and core visibility separately. Missing cursor theme fields resolve to an opaque default; the lifecycle change does not itself hide the cursor.

On fresh main b34ba2de9ad4, the constructor has no cursor/accent theme fields and ready/exit handling changes stdin only. The mounted terminal and retained CSS provide no exit-dependent cursor suppression.
