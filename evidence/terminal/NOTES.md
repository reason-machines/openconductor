# Terminal: reference behavior vs our implementation

Implementation: [`src-tauri/src/terminal/`](../../src-tauri/src/terminal/mod.rs) (`portable-pty` 0.9.0 + `libc`, no Tauri types).
Tests: unit tests beside each file plus PTY tests in [`tests/`](../../src-tauri/src/terminal/tests/mod.rs), run with [`tools/terminal/run-rust-tests.sh`](../../tools/terminal/run-rust-tests.sh) until the Tauri crate declares `mod terminal;`. The Terminal workflow runs them with clippy and rustfmt on macOS and Linux.

Ledger obligations: `term.pty` (spawn, write, resize, kill, flow control, history persistence, mirrors) and `term.shell-exec` (`execute_shell_command[_cancellable]`, cancel). See [`../ledger/README.md`](../ledger/README.md).

## Our choices where the reference is not observable

- IPC ([`terminal_commands.rs`](../../src-tauri/src/terminal_commands.rs), payloads in [`wire.rs`](../../src-tauri/src/terminal/wire.rs)): the reference's `pty_spawn`, `pty_write`, `pty_resize`, `pty_kill`, `pty_ack_bytes`, plus our `pty_read_history`, `pty_clear_history`, `pty_list`. Events go out on one `pty-event` channel tagged `kind: ready | data | exit` with the terminal id; data is base64 so a UTF-8 sequence split across reads arrives intact. The app kills every terminal on exit.
- Watermarks: 512 KiB high, 128 KiB low. Default history: 1 MiB. The reference values were not recovered.
- `TERM=xterm-256color`, `COLORTERM=truecolor`; default program is the user's login shell (`$SHELL`, else passwd).
- An exited terminal stays readable (history, exit status) until `kill`; writes to it fail with `NotRunning`.
- Line-editing shortcuts send the bytes readline and zsh bind to the same motion: Cmd+Left `^A`, Cmd+Right `^E`, Cmd+Backspace `^U`, Option+Left/Right `Esc b`/`Esc f`, Shift+Enter `Esc Enter` (a literal newline in zsh and agent CLIs). The reference's bytes were not recovered.
- Selection colours: the accent colour at 40% (focused) and 30% (unfocused), so a find match stays visible while the find input has focus. The reference's terminal theme was not read.
- Terminal font: kept in settings.toml under `[appearance]` with Conductor's key names (Conductor keeps them in its settings table, and the size as a string). The family input saves on Enter or blur, not on each keystroke with a debounce as Conductor does, and refuses the characters the Mono Font input refuses (quotes, `\`, `;`, braces, `<>`); Conductor puts the text in unvalidated. Sizes outside 10-20 are refused by the backend; Conductor's slider only offers 10-20 but parses any stored value. Mutation check (by hand, once): not setting the size on live terminals, or not pushing settings to the terminal at all, each fails the e2e test.
- Scrollback limit: kept in settings.toml under `[advanced]` with Conductor's key, as a number (Conductor keeps a string in its settings table). Conductor falls back to its older `terminal_max_buffered_lines` setting (times 5,120 bytes) when the byte limit is unset; we never had that setting, so there is nothing to fall back to. The backend accepts any stored value; the frontend clamps it when reading, as Conductor does. The rest of Conductor's Advanced tab (executable paths, SSH key, remote execution, file sync) is not built. The backend screen copy still keeps its own 2000 rows. Mutation check (by hand, once): not pushing the limit to live terminals, not applying the stored setting, and 80 instead of 160 bytes per row each fail the e2e test.
- Big terminal mode: Conductor opens a big terminal as a center-pane workspace tab (`createTerminalWithCommand`, next to chats and the browser) and binds ⌘⇧T at the workspace level. We have no center-pane tabs yet, so ⌘⇧T with a terminal focused opens a tab in the bottom panel running the preset; ⌘T and the panel's + keep opening plain shells, and a big tab restored after a relaunch starts a plain shell. Our settings have no tool-approval switch and no Claude / Codex / OpenCode executable paths yet (Conductor's Advanced rows), so the commands are always the no-approval table with bare names; the resolver already takes both. Kept in settings.toml as `[experimental] experimental_big_terminal_mode` and `[terminal] big_terminal_preset` plus `[[terminal.big_terminal_custom_commands]]` tables; Conductor keeps a string per key in its settings table, the custom commands as a JSON string (our reader accepts that too). A custom command saves on Enter or blur, not on every keystroke as Conductor's debounced save does, so a slow save cannot overwrite newer typing. Conductor's preset rows show agent icons; ours show labels only.
- Until workspaces carry their worktree path, new terminals open in the repository checkout.
- If a background job keeps the PTY open after the main process exits, the exit event is sent after a 1 s drain grace and any later output still arrives.
- Shell commands: arguments `{ request: { command, cwd?, env? } }` (plus `id` for the cancellable one), result `{ stdout, stderr, exitCode, signal, cancelled, truncated }`. They run as `/bin/sh -c` with stdin closed, keep 8 MiB per stream, and return 0.5 s after the shell exits even if a background job holds the pipes. None of these shapes or limits were recovered from the reference.
- Screen and mirror commands take one `args` object as the reference sends them; the older `pty_*` commands keep their flat arguments (the reference wraps those too, and names the ack count `byteCount`). Terminals keep 2000 scrollback rows on the backend screen (the reference's client-side default). A mirror's `maxBufferedBytes` becomes `bytes / cols` rows (at least one screen, at most 100,000), since we keep rows, not bytes; without it, 2000. Creating a mirror id that exists starts it over blank. None of these limits were recovered from the reference.
- Screen snapshot ANSI: one SGR per attribute change (reset, then everything the cell draws with: bold, dim, italic, underline styles `4:2`-`4:5`, inverse, hidden, strike, 16 / 256 / RGB colours, underline colour), wrapped rows written full width with no line break, coloured trailing blanks kept, every screen row written when there is scrollback, then `ESC[row;colH` for the cursor. In the alternate screen the snapshot is that screen only (the primary screen is not carried). Hyperlinks (OSC 8), cursor shape and visibility, and a pending wrap at the last column are not carried. The reference's serializer was not recovered.
- Terminal history: load returns `null` when either the row or the encrypted entry is missing (the reference's backend behaviour for a half-saved session was not recovered). Persist writes the entry before the row, as the reference's frontend store does. A stored key that is not base64 of 32 bytes is an error, never replaced, so saved entries are not silently orphaned. Our Keychain item is under our own service name (`com.reasonmachines.openconductor`), not Conductor's; off macOS the secret store is in memory, so history saved there cannot be read after a restart. Our frontend has no local-storage layer yet, so the backend is the only writer of `local-storage.metadata.json`; once the frontend writes it too, both need one lock or one owner. Deleting saved sessions and the reference's startup cleanup of entries with no row are not built (the reference does both from its frontend); a closed tab's record stays on disk until the 50 MiB limit evicts it, but is never restored because its tab is gone from the list.
- Cold restore: the tab list is kept in the webview's `localStorage` under the reference's name `terminal-panel-tabs-v1`, as `{ [workspaceId]: { tabs: [{ id, title, cwd }], activeId, next } }`; the reference keeps it in its own local-storage subsystem `terminal` (100 MiB) as a flat `terminals` array, which our frontend does not have yet. Tab id, PTY id and saved session id are one id (the reference gives the PTY its own random id). Every saved tab respawns when its workspace's panel first shows (the reference spawns a tab when its view mounts). Saves run at most once per second per terminal and never two at once, rather than on idle: WKWebView has no `requestIdleCallback`, where the reference falls back to saving after every output batch. A last save is attempted on `pagehide`.

- Deleting saved sessions: the reference deletes from its frontend (SQL through its database plugin, entries through its local-storage layer), so it has no backend delete command; ours are our own commands over the backend store, since the backend is the only writer of both halves here. A delete removes the row first, then the entry (the reference starts both at once), so an entry left by a failed removal has no row and the next launch's cleanup removes it. The cleanup runs before the first history call of a launch, not when the app starts (the reference runs it when its store backend is constructed): ours needs the Keychain key to open the store, and the first call already reads it. Each call reads the key once and passes it to the cleanup. A cleanup that fails is retried by the next call; the reference logs it once and does not retry. Workspace removal is detected as a workspace leaving the app state (archive, or its repository removed); the reference also does it when the root path changes, which we do not have.
