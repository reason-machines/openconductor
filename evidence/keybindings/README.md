# Keyboard shortcuts (Conductor v0.87.6)

Evidence for the shortcut registry, the "Keyboard shortcuts" help dialog and the
`/settings/user/key-bindings` editor. All strings come from a third-party app:
untrusted data, kept only to match behaviour.

## Files

- `keybindings.json` - generated by `node tools/keybindings_extract.mjs <decoded index-*.js>`.
  `commands` holds all 165 registry entries in source order. The other fields are
  the storage key, category order, send-key presets, conflict scopes and legacy
  override aliases. Generated from the full `index-BGEQ8YjU.js` chunk on Sven's Mac
  (3,493,297 bytes, sha256 `b5b01f33…`, matching
  `evidence/frontend/tauri-assets-manifest.json`). An earlier run on a byte slice
  holding the registry module produced identical data.

## Cross-check with evidence/search-palette

`evidence/search-palette/keybindings.json` (#19) was extracted independently from
the same chunk. Both have the same 165 ids in the same order, with identical
`title`, `category`, `configurable`, `hidden` and `when`. They differ on keys for
24 commands, all because #19 leaves bindings out: 20 commands bound with
physical keys (`pn({code,display})`, for example `toggleTheme` Cmd+Option+T and
the `]` alternate on `nav.nextTab`), plus the four send-key commands, whose
defaults #19 takes from the send-key mode map instead. This file is the
reference for keys.

## Registry

Each command has `id`, `key` (the primary shortcut), optional `additionalKeys`,
`title`, `category`, `configurable`, optional `hidden`, `displayScope`,
`description`, and `when`:

- `isGlobal`, `enableOnInputFocus`, `allowWhileTyping`, `enableOnDialogIds`,
  `enableOnTerminalFocus`, `requireTerminalFocus`.

A shortcut is `{key, modifiers?}`. The key is either `logical`
(`{kind:"logical", value}`, compared with `KeyboardEvent.key`, case-insensitive
for letters, `+` also matches `=`) or `physical`
(`{kind:"physical", code, display}`, compared with `KeyboardEvent.code`; used for
most Option and Control+Command chords, where macOS changes `key`). Modifiers are drawn from
`ctrl, meta, shift, alt` and always shown in that order.

Counts: 165 commands, 7 categories, 142 configurable, 61 hidden, 23 fixed.

Display glyphs: meta `⌘`, shift `⇧`, ctrl `⌃`, alt `⌥`, enter `↵` (an icon in
the UI), escape `Esc`, tab `Tab`, backspace `⌫`, arrows `↑ ↓ ← →`, space `Space`.
Any other key is shown upper-cased.

## Overrides

Overrides are stored as a JSON string in the `settings` table under
`keybinding_overrides_v1`: `{"version":1,"overrides":{"<commandId>": shortcut | shortcut[]}}`.
When the file is read:

- a wrong version, invalid JSON or a non-object gives no overrides;
- unknown or non-configurable ids are dropped, and so is any entry with an invalid shortcut;
- the legacy aliases (`legacyAliases`) are mapped to their current ids when the current id is unset;
- the legacy `message_send_key` setting (`enter` / `cmd-enter`) picks which
  `sendKeyPresets` apply to `chat.newLine`, `chat.submitMessage`,
  `chat.submitOppositeFollowUp` and `chat.question.submit`.

An override replaces the primary key and all additional keys. Resetting a command
deletes its entry. Writes are serialized, and each write reads the current value first.

## Conflicts

Two commands conflict only when both are in the same scope group. The groups are
`conflictScopes.base` plus each entry of `conflictScopes.groups` (routine editor,
chat composer, queued-message edit, question card, terminal, diff). The editor
refuses a recorded shortcut that another command in a shared group already uses.
It shows "Already used by <title>. Type another shortcut." and keeps recording.
The check runs over every command, hidden ones included, and a key conflicts when
it fires on the pressed event or is equivalent to the recorded shortcut. So
re-recording Cmd+K for the palette reports "Clear terminal scrollback"
(`renderApp-D_fmY7hW.js`, the recorder's keydown handler).

## Dispatcher

From `renderApp-D_fmY7hW.js` on Sven's Mac (a zustand store with
`register`/`unregister`/`dispatch`; window keydown listener in the capture phase,
plus a bubble-phase one for a bare Escape that nothing else took).

- Priorities: LOW 10, NORMAL 50, HIGH 100, TERMINAL 150, DIALOG 200.
- Ignored: keys while a `[data-keybinding-recorder-active="true"]` element is in
  the event path, and lone Meta/Control/Alt/Shift.
- Focus: typing means an INPUT or TEXTAREA in the event path, or a
  contenteditable element; terminal means the target is inside `[data-terminal]`.
- Backspace outside a text field is always `preventDefault`ed. A bare Escape
  while typing (not in a terminal) blurs the field and stops there.
- A handler fires when its scope is focused, the key and modifiers match, and
  `when` allows it: terminal focus needs `enableOnTerminalFocus`;
  `requireTerminalFocus` needs terminal focus; a shortcut without modifiers needs
  `allowWhileTyping` or `requireTerminalFocus` while typing or in a terminal;
  `isGlobal` then passes; otherwise typing needs `enableOnInputFocus`; listed
  `enableOnDialogIds` need that dialog open, and unlisted handlers need no dialog.
- A held-key repeat runs only handlers with `allowRepeat`; with none, the event
  is swallowed.
- Order: priority, then more modifiers first. A callback returning `false`
  passes to the next. The first that takes it sends `keyboard_shortcut_used`
  with `keybinding_id`, plus `active_dialog_id` and `telemetry_context` when set.

## Registration (`oi` hook)

From `renderApp-D_fmY7hW.js`: components bind a command with
`oi(commandId, callback, options)`. It registers one handler per effective
shortcut (overrides applied) with `when` merged as: the enclosing dialog's id
(`enableOnDialogIds`), then the command's registry `when`, then `options`.
Missing flags default to `enableOnInputFocus: true`, `enableOnTerminalFocus: true`,
`isGlobal: false`, `requireTerminalFocus: false`, `allowWhileTyping: false`,
priority NORMAL. `options.enabled === false` registers nothing. Workspace
navigation passes `{telemetryContext: "workspace-navigation"}`. Ours:
`bindingsFor` and `resolveCommand` in `src/keybindings/resolve.ts`.

## Window listeners

From the same chunk (the component that mounts the dispatcher, next to the
`vd` priority table). It adds five `window` listeners:

- `keydown`, capture phase: an installed key capture takes the event first;
  otherwise a bare Escape is skipped here and everything else is dispatched.
- `keydown`, bubble phase: a bare Escape that no one `preventDefault`ed is
  dispatched, so dialogs and popovers handle Escape before the global handlers.
- `keyup`, capture phase: goes to an installed key capture.
- `compositionstart` and `beforeinput`, capture phase: `preventDefault` while a
  key capture is installed, or within 50 ms after a handler took an Option chord
  without Command or Control (so ⌥T does not also type †).

A key capture (`{ onKeyDown, onKeyUp }`) is exclusive: installing one replaces
the last, and its remover only clears it if it is still current. While it is
installed every keydown and keyup is `preventDefault`ed, stopped and handed to it.
The shortcut recorder and the key-bindings page's "Type shortcut" search use it.
When a handler runs or a repeat is swallowed, the event is also stopped
(`stopImmediatePropagation`) and the Option-chord timer starts.

## Help dialog (`openKeyboardShortcuts`, default ⌥⌘/)

- Title "Keyboard shortcuts" with an icon, and a search input "Search shortcuts...".
  The dialog is `max-w-3xl h-[80vh]`.
- Rows are commands that are not `hidden` and have no `enableOnDialogIds`.
  That gives 104 rows, grouped under `categoryOrder` headings. Each row is the
  title on the left and its effective shortcuts on the right, joined by "or",
  each part in a `<kbd>`.
- A non-empty query fuzzy-matches title and category with the bundled fuzzysort
  3.1.0 (its accent stripping identifies the version), threshold 0.5. Per row,
  a field scoring under 0.5 is skipped and the best remaining field wins; rows
  sort by that score, ties in registry order. Only a title match is highlighted
  (matched characters normal, the rest `opacity-50`); a row found by its category
  shows its plain title. With no results it shows `No shortcuts found for "<query>"`.
  Source: the `WZ` search helper and `u2` highlighter in `renderApp-D_fmY7hW.js`.
- Opened by the shortcut, the command palette entry "Show keyboard shortcuts",
  a "Keyboard shortcuts" popover menu item, and the native event
  `open_keyboard_shortcuts_dialog`. The shortcut and the native event both
  toggle the dialog (close it if open).

## Native menu

"Keyboard Shortcuts". Clicking it emits the `open_keyboard_shortcuts_dialog` event
to the webview. It logs `Failed to emit keyboard shortcuts dialog event: ` on error,
and `Warning: Could not add Keyboard Shortcuts menu item` if the item cannot be added.
These strings come from `MacOS/conductor`.

The same string run (0.87.6, `strings -a` on `MacOS/conductor`, re-read
2026-11-05) holds every item Conductor adds, in this order, each followed by its
own `Warning: Could not add <label> menu item`:

- `Check for Updates`; `Settings...` with `CmdOrCtrl+,`; `custom_quit` with `Cmd+Q`.
- `toggle_left_sidebar` "Toggle Left Sidebar", `toggle_right_sidebar` "Toggle Right Sidebar".
- Help: `keyboard_shortcuts` "Keyboard Shortcuts" (no accelerator), `documentation`,
  `best_practices` "Best Practices", `changelog` "Changelog", `send_feedback` with
  `CmdOrCtrl+Alt+f`, `submit_a_prompt` "Submit a Prompt...", `diagnostics`
  "Diagnostics...", `debug` with `CmdOrCtrl+Alt+i`.
- The events they emit: `open_diagnostics_page`, `open_submit_prompt_dialog`,
  `open_changelog_url`, `open_best_practices_url`, `open_feedback_dialog`,
  `open_keyboard_shortcuts_dialog`, `open_documentation_url`.

The binary also holds Tauri's `__tauri_help_menu__` and `__tauri_window_menu__`

OpenConductor: `src-tauri/src/menu.rs` appends Keyboard Shortcuts to the default

### Settings... and Quit (re-read 2026-11-06)

- `Settings...` carries the accelerator `CmdOrCtrl+,`. The webview listens for
  `open_settings_page` and, on it, closes any dialog and opens
  `/settings/user/general` (renderApp-D_fmY7hW.js @ ~10,884,627). After building
  the menu, the binary looks `Settings...` up by label to set the `gearshape` SF
  Symbol (`Warning: Could not find Settings... menu item`,
  `Warning: Could not load gearshape SF Symbol`).
- `custom_quit` carries `Cmd+Q` and replaces the predefined Quit. Clicking it logs
  `Custom quit menu item clicked` and emits `quit_requested`
  (`Failed to emit quit_requested event`). The binary registers the commands
  `set_quit_handler_ready(ready)` and `quit_app`.
- The webview registers its `quit_requested` listener, then calls
  `set_quit_handler_ready(true)` (`v5a` @ ~11,073,980). On a request (`b5a`):
  source `system` quits at once; otherwise, if any local agent is running, it
  opens the confirm dialog `y5a`, else quits. The dialog: title "Quit Conductor?",
  text "No agents are running, so it's safe to quit." / "1 agent is currently
  running and will be stopped." / "N agents are currently running and will be
  stopped." / "Agents may be running and will be stopped." (count unknown),
  buttons Cancel and a destructive `data-primary-action` "Quit ⌘↵".
- The registry's `quitApplication` (⌘Q) has no `oi()` call in renderApp: Quit is
  native-only there.

OpenConductor: `menu.rs` adds `Settings...` (id `settings`, `CmdOrCtrl+,`) after
About and swaps the predefined Quit for `custom_quit` (`Cmd+Q`);
`src-tauri/src/app_quit.rs` holds the ready flag and `quit_app`;
`src/features/quit/` is the dialog. `quitApplication` is also bound in the
webview (`src/App.tsx`), so ⌘Q follows the same path where there is no native
menu. Differences: the `system` source (quit from the Dock or the OS) is not
routed through the webview; the running count is the chat store's
`working`/`cancelling` chats plus workspaces that report `working` without a chat
status; no `gearshape` icon; dialog title says OpenConductor.

## Key-bindings page (`/settings/user/key-bindings`)

- Gated by `internal_settings_enabled` (or dev mode). Without it, the route
  redirects to `/settings/user/general`.
- Header "Keyboard shortcuts" and a search box "Search keyboard shortcuts...".
  The search matches title, category, command id and key names (for example
  "cmd", "command", "⌘"). Pressing a modifier in the empty box switches it to
  "Type shortcut" mode, which filters by the shortcut you press.
- Rows are commands with `configurable || !hidden`. `chat.submitOppositeFollowUp`
  is hidden unless queued messages are enabled. Rows are grouped by category in
  bordered lists.
- Configurable commands show a recorder button. While recording, it shows
  "Type shortcut" or the held modifiers. Escape with no modifiers cancels. Saving
  writes the override, and a failed save shows the toast "Failed to save keyboard shortcut".
  A "Reset" button appears when the command is customized.
- Fixed commands show a lock icon and "Fixed shortcut" for screen readers.
  These are commands with `configurable:false`, plus the four send-key commands,
  which the message-send setting controls instead.

Detail from the page (`lEa`) and row recorder (`rEa`) in `renderApp-D_fmY7hW.js`
(sha256 `5199d392…`, from offset 11,218,000), modelled in `src/keybindings/editor.ts`:

- Search uses the shared multi-field ranker (`WZ`, threshold 0.5) over
  title, category, command id and a key text built per key part: `meta` gives
  "command cmd ⌘", `ctrl` "control ctrl ⌃", `alt` "option alt ⌥", `shift`
  "shift ⇧", any other part itself plus its glyph.
- "Type shortcut" starts only when the box is empty, no typed shortcut is
  showing, and the key is a modifier. It takes exclusive key capture; the box
  shows the held modifier glyphs. The first recordable key sets the box to its
  glyphs ("⌘K") and filters to rows with a key that fires on that press. Typing
  in the box or blurring it leaves the mode. A query with no matches shows
  nothing: there is no empty-state text.
- Both recorders ignore repeats and IME composition, show held modifiers, and
  treat a bare Escape as cancel. A modifier keydown also clears a shown
  conflict. A recorded shortcut saves as a one-key override, and the row stops
  recording before the save resolves. Blurring the row button cancels.
- The row button's accessible name is "Change shortcut for <title>. Current
  shortcuts: <Command+K or ...>." and, while recording, "Recording shortcut for
  <title>. Press modifiers and a key." or "... Held modifiers: Command+Option.
  Press a key.", also announced in a polite live region. The conflict line has
  `role="alert"` and id `keybinding-conflict-<commandId>`.
- Recorder buttons are disabled while overrides are loading. Queued messages
  default to off, so the opposite follow-up row is hidden until that flag loads.

OpenConductor: `src/settings/KeyBindingsPage.tsx` at `/settings/user/key-bindings`,
listed as "Keyboard shortcuts" under Personal. Two deliberate differences:

- It is not gated. OpenConductor has no `internal_settings_enabled` flag, so
  gating would make the page unreachable. The nav label is ours; Conductor's
  internal-settings nav entry was not read.
- Overrides are stored as the same `keybinding_overrides_v1` JSON string, but at
  the top level of the settings file (the backend keeps keys it does not model)
  instead of a `settings` table row. They are read once at startup by
  `KeybindingsProvider` and written through the settings page's own save, so a
  later change on another settings page cannot overwrite them with a stale copy.
  A failed save shows the toast "Failed to save keyboard shortcut".

## REA gaps

- Settings... item id, its position in the app menu, and the label of `custom_quit`
  are not in the string table and were not decompiled (`rea search` on
  `MacOS/conductor` fails with `provider_unavailable`; no Ghidra/Hopper/IDA/Kuna
  and no Java runtime on Sven's Mac, re-checked 2026-11-06). The running-agent
  counter that `y5a` calls (`tPt` over sessions and workspaces) lives in a chunk
  where the minified name does not resolve by string search; its status set was
  not read.

- `analyze-javascript-application` finds no IPC operations: it does not model
  Tauri `invoke` or `listen`. The registry and event wiring were located by
  string search on the decoded bundle, sliced by brace matching, and evaluated
  with stub constructors (`tools/keybindings_extract.mjs`).
- The key-bindings page and recorder were read by byte offset in the decoded
  `renderApp` chunk. REA has no view that addresses a minified JavaScript
  function by name or offset, and its earlier `analyze-javascript-application`
  run on the index chunk (90 MB of JSON) holds none of these strings.
- No component tree: the bundle is minified and has no source maps. Component
  behaviour above comes from reading the minified React output.
- `rea execute-rizin-command` on Sven's Mac fails with `capability_unavailable`
  (rizin not installed, ENOENT), and `rea function` on the menu-event closure
  `conductor_lib::run` at `0x100498360` fails with `provider_unavailable`: Ghidra,
  Hopper, IDA and Kuna are all unconfigured there (no Java runtime). So the menu
  builder was not decompiled; the native menu table above is from the string table.
