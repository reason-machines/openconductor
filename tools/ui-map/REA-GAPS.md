## REA gaps and bugs hit while building this map

REA 6.7.0 (`rea-agents`), Linux cloud machine, Chromium 1.x headless. Each was hit in this run.

1. **No UI-structure model for a Tauri/React bundle.** `analyze-javascript-application` on the decoded frontend (evidence/frontend) yields modules, call sites and literals, but no component tree, route table, dialog/menu/toast inventory or settings schema, and its IPC summary is Electron-only (0 operations for Tauri `invoke`). The inventory here is a regex pass over the minified chunks (`tools/ui-map/extract_inventory.py`), not REA output.
2. **The application graph is budget-truncated.** The semantic graph stops at 100,000 nodes with 1,876 limitations ("Resource constraint during analyze_javascript_application"), mostly in the 11.6 MB `renderApp` chunk that holds every screen, so REA cannot answer "which component renders this string".
3. **`capture-browser-scenario` fails the whole scenario on one bad locator** and names no step: the result is `execution_failure` with an empty or `screenshot undefined` artifact. `capture_ref.mjs` works around it by retrying shorter action prefixes and records the first action that failed (`menu-repo-actions`: clicking `[aria-label='tide-web actions']` after a hover).
4. **No way to tell a redirect from a render.** A scenario that lands on a different route (the frontend redirects gated settings pages to `/settings/user/general`) is reported as a successful capture; only the final `url` artifact shows it. `build_map.py` compares it with the requested path and marks those references `redirected`.
5. **`compare-web-screenshots` returns only a changed-pixel count and ratio.** No region boxes, no per-element diff and no diff image, so it cannot attribute a difference to a panel or row; the side-by-side diff images are drawn outside REA (Pillow).
6. **No native capture for the reference on this machine.** `capture-native-ui-scenario` and `observe-native-ui` need the Mac with Screen Recording and Accessibility, so the reference is the extracted frontend in Chromium, not Conductor's WKWebView window; native chrome (traffic lights, vibrancy, menus bar) is not measured.
7. **No WebKitGTK/tauri-driver capture tool.** REA cannot drive a Tauri app; the OpenConductor side uses WebDriver directly (tests/e2e), so its screenshots carry no REA Evidence id, only sha256.
8. **`--schema` for `capture-browser-scenario` still shows only `inputJson: string`**, so the accessibility and DOM capture options were found by trial (`capture.at_end: ["screenshot","url","dom","accessibility"]`).
9. **Role locators accept only 14 roles** (REA 6.8.0): `{kind: "role", role: "treeitem"}` is rejected as `invalid_value`, so tree rows (the right panel's All files tree) need a CSS locator.
10. **No `hover` action** in 6.8.0's `capture-browser-scenario` contract (`goto, click, fill, press, select_option, check, uncheck, wait_for, request, wait_for_timeout`); a hover step is rejected as invalid input.
11. **A Chromium launch crash is reported as a bare `execution_failure`.** With a long `TMPDIR` Chromium aborts on "Socket path too long" for its singleton socket; REA only says "run `rea doctor`" with `cleanup_incomplete`. Set `TMPDIR` to a short path (for example `/tmp/t`).
12. **A `wait_for` whose text locator matches two elements fails the scenario as "screenshot missing".** On the repository Misc page `text=tide-web` matches the nav item and the root path, Playwright's strict mode rejects it, and REA reports only a missing screenshot (no step id, no "strict mode violation"). The Misc state now waits on the page description instead.
13. **No network-request view of the scenario.** REA records console and page errors but not the page's requests or the Tauri IPC behind them, so the cause of the repository-settings redirect (a failed `GET /organizations` inside Conductor's user service) was found by patching the bundle in Playwright and logging store writes, not with REA.

Harness limits that shape the reference (not REA bugs): settings pages behind an organization or feature flag (`ports`, `key-bindings`, `terminal`, `internal`, `organization/*`, `cloud/setup`) redirect to General; `/dashboard` redirects to `/`. The `repos/$repoId/*` pages used to redirect too: Conductor's repository guard (`fHi`) sends any organization *error* to General, and the mock refused every network call. The mock now answers `POST /auth/exchange` and `GET /organizations` (an empty list, a local-only account) from `HTTP_FIXTURES` in `tools/screens/tauri-mock.js`, over the same `plugin:http` channel protocol Conductor reads, so those five pages render.

### Hit while building Settings › Repository › Scripts and Actions (REA 6.8.0)

18. **`capture-browser-scenario` cannot open a context menu.** It has no right-click action (`click` takes no `button`), so the "right-click menus" checklist item was checked with Playwright: on Conductor's Scripts page a right-click on the editors, the Add button and the share link opens no menu and sends no `plugin:menu|*` IPC.
19. **No dialog or popover state in a scenario's DOM capture.** Base UI portals the Add/Edit run-script dialog outside the page root; the scenario's `dom` artifact has the overlay but the popup had to be measured with a Playwright walk of `[role=dialog]`.
20. **Minified cross-chunk names still need manual tracing.** `ama` (run scripts) calls `qje`/`bAn`/`cJ`/`Jw`, imported from `index-BGEQ8YjU.js` as `Szt`/`bzt`/`pf`/`lo`; REA's graph gives no import map, so each was resolved by reading the chunk's export list.
