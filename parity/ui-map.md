## How it was measured

- **Inventory**: `tools/ui-map/extract_inventory.py` over Conductor's decoded Tauri asset table (`renderApp`, `index` chunks). Routes from TanStack route definitions; dialogs, sheets, menus, tabs, selects from Radix/Base UI components named by `displayName`; toasts from sonner calls; popovers from popover-surface classes; empty states from their copy; settings pages and rows from [evidence/settings/settings-registry.json](../evidence/settings/settings-registry.json) (REA-extracted). Copy is untrusted data, kept for matching only.
- **Conductor reference**: `tools/ui-map/capture_ref.mjs` renders the extracted frontend in Chromium through the `tools/screens` harness (Tauri IPC mocked with sql.js databases built from the evidence schemas and synthetic seed rows) and captures each state with REA `capture-browser-scenario` (screenshot, URL, DOM).
- **OpenConductor**: `tools/ui-map/oc_lane.mjs` drives the built debug app (`npx tauri build --debug --no-bundle`) through tauri-driver and WebKitWebDriver under Xvfb, the same lane as `tests/e2e`, on an isolated HOME seeded with repos tide-web, tide-api, dotfiles and one workspace. Window screenshot plus the visible DOM text.
- **Diff**: `tools/ui-map/compare.mjs` runs REA `compare-web-screenshots` at channel thresholds 0 and 24 for every state with both captures; `diff/<state>.jpg` is reference | OpenConductor | changed pixels (threshold 24).
- **Status** (per state, and per item through the state it appears in):
  - **matches**: the reference rendered the state, OpenConductor reached it, the item's copy is on screen in both, at least 90% of the reference's UI copy is on OpenConductor's screen, and the state differs by at most 5% of pixels at channel threshold 24.
  - **wrong**: OpenConductor shows it (its copy is in a capture of the running app) but it is not shown to match: the diff or copy is over the bar, or there is no valid reference render to prove a match.
  - **missing**: OpenConductor has no way to reach the state, shows a different screen there (under 25% of the reference's UI copy), or the item's copy is in no capture of the running app.
- UI copy means rendered strings that are literals in Conductor's bundle (`ui_strings` in inventory.json), so invented seed data (repo, workspace and user names) never counts. The OpenConductor brand name is normalised to Conductor before matching.
- **Side-by-side records** ([ui-map/side-by-side.json](ui-map/side-by-side.json)): a builder who fixes a state captures both apps in that state with REA `capture-browser-scenario` (`tools/side-by-side/*.mjs`, Conductor's extracted frontend in the `tools/screens` harness beside OpenConductor's built frontend in Chromium with Tauri IPC mocked) and scores the pair with REA `compare-web-screenshots`, at the map's viewport. The record stands in for both captures of that state, under the same status rules, until the OpenConductor lane captures the state again; its rows link the committed side-by-side image and name the lane in `openconductor.note`.

- Seed data differs between the two sides (the reference harness seeds six workspaces with a transcript; the OpenConductor seed has one real git worktree), so the pixel ratio carries some content difference too. The copy check and the side-by-side images are the better guide to what to fix.

## REA gaps and bugs hit while building this map

REA 6.7.0 (`rea-agents`), Linux cloud machine, Chromium 1.x headless. Each was hit in this run.

1. **No UI-structure model for a Tauri/React bundle.** `analyze-javascript-application` on the decoded frontend (evidence/frontend) yields modules, call sites and literals, but no component tree, route table, dialog/menu/toast inventory or settings schema, and its IPC summary is Electron-only (0 operations for Tauri `invoke`). The inventory here is a regex pass over the minified chunks (`tools/ui-map/extract_inventory.py`), not REA output.
2. **The application graph is budget-truncated.** The semantic graph stops at 100,000 nodes with 1,876 limitations ("Resource constraint during analyze_javascript_application"), mostly in the 11.6 MB `renderApp` chunk that holds every screen, so REA cannot answer "which component renders this string".
3. **`capture-browser-scenario` fails the whole scenario on one bad locator** and names no step: the result is `execution_failure` with an empty or `screenshot undefined` artifact. `capture_ref.mjs` works around it by retrying shorter action prefixes and records the first action that failed (`menu-repo-actions`: clicking `[aria-label='tide-web actions']` after a hover).
4. **No way to tell a redirect from a render.** A scenario that lands on a different route (the frontend redirects gated settings pages to `/settings/user/general`) is reported as a successful capture; only the final `url` artifact shows it. `build_map.py` compares it with the requested path and marks those references `redirected`.
5. **`compare-web-screenshots` returns only a changed-pixel count and ratio.** No region boxes, no per-element diff and no diff image, so it cannot attribute a difference to a panel or row; the side-by-side diff images are drawn outside REA (Pillow).
6. **No native capture for the reference on this machine.** `capture-native-ui-scenario` and `observe-native-ui` need the Mac with Screen Recording and Accessibility, so the reference is the extracted frontend in Chromium, not Conductor's WKWebView window; native chrome (traffic lights, vibrancy, menus bar) is not measured.
7. **No WebKitGTK/tauri-driver capture tool.** REA cannot drive a Tauri app; the OpenConductor side uses WebDriver directly (tests/e2e), so its screenshots carry no REA Evidence id, only sha256.
8. **`--schema` for `capture-browser-scenario` still shows only `inputJson: string`**, so the accessibility and DOM capture options were found by trial (`capture.at_end: ["screenshot","url","dom","accessibility"]`).
9. **Role locators accept only 14 roles** (REA 6.8.0): `{kind: "role", role: "treeitem"}` is rejected as `invalid_value`, so tree rows (the right panel's All files tree) need a CSS locator.
10. **No `hover` action** in 6.8.0's `capture-browser-scenario` contract (`goto, click, fill, press, select_option, check, uncheck, wait_for, request, wait_for_timeout`); a hover step is rejected as invalid input (`invalid_request` at `actions[n].action`), which `capture_ref.mjs` then reported as `screenshot undefined`. There is no scroll action either: the lower half of the repository Misc page (`settings-repo-misc-lower`) is reached by clicking the Files to copy preview note, which Playwright scrolls into view first.
11. **A Chromium launch crash is reported as a bare `execution_failure`.** With a long `TMPDIR` Chromium aborts on "Socket path too long" for its singleton socket; REA only says "run `rea doctor`" with `cleanup_incomplete`. Set `TMPDIR` to a short path (for example `/tmp/t`).
12. **A `wait_for` whose text locator matches two elements fails the scenario as "screenshot missing".** On the repository Misc page `text=tide-web` matches the nav item and the root path, Playwright's strict mode rejects it, and REA reports only a missing screenshot (no step id, no "strict mode violation"). The Misc state now waits on the page description instead.
13. **No network-request view of the scenario.** REA records console and page errors but not the page's requests or the Tauri IPC behind them, so the cause of the repository-settings redirect (a failed `GET /organizations` inside Conductor's user service) was found by patching the bundle in Playwright and logging store writes, not with REA.
14. **No layout or geometry capture.** `capture-browser-scenario` returns screenshot, url, DOM and accessibility, but no element boxes (no `getBoundingClientRect`, computed styles or text line boxes) and has no evaluate action, so the sidebar alignment sweep (`tools/sidebar-screens/measure-alignment.mjs`) measures both apps with playwright-core directly; its numbers carry no REA Evidence id. The DOM artifact has no geometry either.
15. **REA's click and Playwright's click disagree on Conductor's repo header.** Through REA, `click` on `text=tide-web` expands the repo; the same locator clicked in playwright-core 1.64 (same Chromium, viewport, reduced motion and blocked service workers) does nothing, because the header is a @hello-pangea/dnd drag handle that swallows the pointer sequence. A dispatched DOM `click` expands it. REA does not record which input path its click used, so the difference cannot be explained from the Evidence.
16. **Hover states don't render in Conductor's headless capture, and REA has no hover action to force them.** Conductor gates its row hover controls on `@media (hover:hover)` group-hover, which headless Chromium doesn't match, so the repo row's "..." button stays at opacity 0 in every capture. `capture-browser-scenario` (REA 6.7.0) has no hover action and no way to emulate the `hover` media feature: its action kinds are `goto`, `click`, `fill`, `press`, `select_option`, `check`, `uncheck` and `wait_for_timeout`, and the string `hover` doesn't appear in `rea-agents/dist/mcp/browserScenario-BRUz7yN0.js` or its contract, so it can't capture the hovered row either. The alignment sweep therefore places Conductor's "..." from the DOM structure (`getBoundingClientRect` via playwright-core: 24×24 at x=189, y=219, the same as ours) rather than from a screenshot, and Conductor's side of the hover crops shows the row unhovered.

22. **No motion capture.** `capture-browser-scenario` takes one screenshot at the end of a scenario: no frame sequence, no fake clock and no way to pause or seek CSS transitions, WAAPI or framer-motion animations, so it cannot show or time a transition.
